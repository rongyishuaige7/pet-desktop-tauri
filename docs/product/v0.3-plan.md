## 1. 要让用户完成什么

产品主线继续是本地桌面陪伴：用户随时能控制打扰，出错后知道发生了什么，花时间制作的伙伴能够保留与恢复。

| 用户任务 | 当前阻碍 | 本轮设计成果 |
| --- | --- | --- |
| 开会前收起、结束后找回 | 小窗口核心控制在首屏之外；伙伴架没有当前伙伴的唤回入口 | 首屏可操作，在当前卡片原地恢复 |
| 暂时安静，稍后回来 | 休息固定一小时；暂停、自主活动、低动态叠加后不易理解 | 15/30/60 分钟休息，明确实际状态与原因 |
| 操作失败后继续 | 资料保存与桌面显示可能给出矛盾反馈 | 区分完成、部分完成、失败，精准重试 |
| 误移除伙伴 | 确认框后无法撤销 | 持久的最近移除与安全撤销 |
| 导入或制作自己的伙伴 | 入口绕、需要理解目录、制作草稿不能长期保留 | 按任务直达，预检、草稿与完整导出 |
| 用照片制作 | 服务配置门槛高，未确认角色就生成整套，重启不能继续 | 配置独立、分阶段确认、持久任务、单动作重做 |

默认仍无需账户、网络服务或照片即可领养和陪伴。不因打开页面、恢复任务或重读资料而显示伙伴或发起付费请求。

## 4. v0.3 的交互设计

### 4.1 陪伴页：控制先于大幅预览

三个主页面和 `stage / shelf / workshop` 标识保持不变。陪伴页从上到下为：标题与真实状态 → 核心操作栏 → 伙伴预览与轻互动 → 折叠的更多动作 → 节奏设置。

| 区域 | ≥1000px | 840–999px |
| --- | --- | --- |
| 状态与核心操作 | 位于预览上方，单一操作栏 | 同样位于预览上方，状态可换行 |
| 预览 | 保留两列内容的舒适比例 | 初始预览高度上限约 220px，避免把控制推到下一屏 |
| 设置入口 | 页面保留一个，侧栏保留全局入口 | 同左，不在节奏区重复放置 |
| 更多动作与预览工具 | 默认折叠 | 默认折叠 |

核心操作栏在 `.app-content` 内吸顶，吸顶时不遮住键盘焦点和恢复提示；不把同一套按钮渲染两遍。840×620、默认字号、无弹层时，收起/唤回、休息和设置无需滚动即可见且可点击。200% 缩放时允许纵向重排，不截断操作或制造横向滚动。

按钮点击目标至少 40×40 CSS px，正文延续 14px，辅助文字不少于 12px，常规文字对比度至少 4.5:1。减少重复的安抚文案，将“收起不删除资料”的说明保留在操作区一次即可。

### 4.2 核心操作随真实状态变化

| 已确认状态 | 主操作 | 次操作 | 状态说明 |
| --- | --- | --- | --- |
| shown + ready | 暂时收起 | 休息…、设置 | 根据暂停/低动态/自主活动显示现有真实状态 |
| hidden + ready | 唤回伙伴 | 休息…、设置 | 已收起，直到你主动唤回；选择定时休息才会到期回来 |
| snoozed + ready | 提前唤回 | 调整休息…、设置 | 到 HH:mm 自动回来 · 约剩 N 分钟 |
| loading / pending | 正在准备 / 正在同步 | 保留设置与查看资料入口 | 保留上一次确认值，不冒充成功 |
| error | 恢复伙伴 | 查看已有伙伴、详情 | 错误原因与可恢复步骤；可停止到期恢复并保持收起 |
| absent | 去领养 | 导入已有伙伴 | 不自动补回或显示已移除资料 |

“保持收起”放在休息菜单中，清除到期时刻；休息态不再同时显示“立即唤回”和“提前唤回”。错误或加载期间，显示/互动可禁用；隐藏及取消休息不能仅因素材未就绪而永久不可操作。

“休息…”用非模态小面板提供 15/30/60 分钟；使用有名称的选项、Escape 关闭并还原焦点。只有选择时长才发送请求。调整休息以本次选择时刻重新计时，不在原到期时刻上累加。托盘提供同样三个时长；旧的一小时调用保持兼容。

到期说明使用“到 HH:mm 自动回来”，必要时包含日期。剩余时间只在页面可见时按分钟刷新，不触发原生状态写回、不每秒朗读。到期是否恢复由 Rust 决定；主窗口关闭、重启和睡眠唤醒继续沿用现有规则。

### 4.3 让偏好与实际效果可解释

不合并或悄悄改写原暂停、自主活动和低动态偏好。界面分两层：开关表达用户选择，邻近说明表达实际生效情况。

| 用户选择与当前条件 | 说明示例 |
| --- | --- |
| 自主活动开，伙伴隐藏 | 已开启，收起期间暂不切换姿态 |
| 自主活动开，显式暂停 | 已开启，动画暂停期间暂不切换姿态 |
| 自主活动开，低动态生效 | 已开启，当前因减少动态而暂停 |
| 自主活动关，无阻断条件 | 保持当前姿态，仍可手动互动 |
| 减少动态跟随系统，系统未开启 | 跟随系统，当前正常播放 |
| 显式暂停，随后关闭低动态 | 动画仍已暂停；不自动恢复播放 |

原因优先级为素材/连接 → 未显示 → 显式暂停 → 减少动态 → 自主活动关闭。对外用“自动切换姿态”，继续避免暗示伙伴会在桌面走动。

### 4.4 伙伴架：在当前卡片解决问题

| 卡片条件 | 主要操作 | 次要操作 |
| --- | --- | --- |
| 当前、显示中 | 回到陪伴 | 重命名、更多 |
| 当前、已收起 | 唤回伙伴 | 重命名、更多 |
| 当前、休息中 | 提前唤回 | 调整休息、更多 |
| 当前、素材错误 | 恢复素材 | 查看详情、更多 |
| 非当前 | 派去桌面 | 重命名、更多 |

当前伙伴按 `activePetId` 标记；原生 petId 不一致时明确“正在同步”或“需要恢复”，不能把其他伙伴的状态贴给它。位置找回仅在支持 `resetPosition` 时提供；隐藏时找回位置不自动唤醒，用户仍需显式唤回。

移除进入“更多”，避免与唤回按钮相邻。操作中的卡片锁定重复提交，其他卡片保持可浏览。任务失败的持续恢复入口也出现在伙伴架，不必先回陪伴页；不同页面共用同一个操作上下文和回调。

### 4.5 操作反馈与恢复

| 实际结果 | 用户反馈 | 后续操作 |
| --- | --- | --- |
| 资料未保存，切换未成立 | 未能保存，原来的伙伴仍保留 | 保留草稿，重试保存 |
| 资料已保存，选择已切换，显示未确认 | 「名字」已保存，等待显示到桌面 | 持续入口“重试显示”；不重复建资料 |
| 已匹配 petId 且原生确认 visible | 「名字」已在桌面陪着你 | 一条短暂成功提示 |
| 只有浏览器预览 | 「名字」已保存，可在网页预览 | 不声称已显示到系统桌面 |
| 回调所属意图或伙伴已经过期 | 已读取最新进度 / 已切换到另一位伙伴 | 刷新界面，撤销旧恢复入口，不执行旧动作 |

成功与失败不能针对同一操作同时出现。成功提示短暂显示，未解决问题保留到解决或用户关闭；关闭只收起面板，页面仍可重新打开。恢复提示说明“已保留什么”和“下一步做什么”，详情仅含脱敏阶段/错误码。

### 4.6 移除、撤销与最近移除

v0.3 将“移除”定义为移到本机的“最近移除”，不删除动作文件或用户原图。最近移除入口位于伙伴架顶部；默认不自动过期，不做后台磁盘清理。

普通伙伴移除后显示“已移到最近移除”及“撤销”，提示至少保留 10 秒，悬停和键盘聚焦时暂停消失。提示消失后仍可从最近移除恢复，跨重启保留。移除当前伙伴时先说明将由谁接替，最后一只则说明桌面将暂时没有伙伴。

两种恢复含义不同：

- 提示中的“撤销”：恢复资料；只有移除后没有发生更新的活动选择，才恢复原活动伙伴；始终保留当前隐藏/休息/暂停偏好。
- 最近移除中的“恢复”：恢复到伙伴架，保留当前活动伙伴；之后可主动派去桌面。

如果撤销期间用户已经切换伙伴，提示“已恢复到伙伴架，当前伙伴保持不变”。重复恢复只保留一份资料。v0.3 不提供自动清空或永久文件删除；空间清理另行设计，不能顺带删除外部目录、内置包或共享素材。

### 4.7 工坊直达与帮助

工坊入口按任务排列：领养现成伙伴、导入已有伙伴、装配动作帧、用照片制作。进入某任务后展示该任务的标题、输入和返回入口，不要求先滚过现成伙伴画廊。

沿用三页面导航，通过受控任务参数切换，不新增路由框架。空集合“导入已有伙伴”直达导入；伙伴架“制作新宠物”进入任务选择；素材恢复携带待修复 petId，不能误走新建。切页保留本次会话输入和所选任务，跨重启草稿由 v0.4 交付。

本批同步补齐表单 label、图标名称、键盘焦点和结果朗读。长任务不能因切换页面而偷偷取消；若当前实现必须留在页面，应在离开前清楚说明并提供继续留在任务的选择。

已有教学保持可跳过。增加可选的“去桌面看看 → 从托盘回来”实践步骤；按能力提供点击/拖动说明。关闭主窗口不增加每次强制确认；不支持的平台不展示无法完成的教学任务。

## 5. v0.4：保住用户制作的成果

> 实施状态（2026-10-23）：A01 自动化实现完成（`inspect_frame_directory`、工坊预检清单、官方目录选择、取消无副作用、拖入目录、无副作用验证、解码总量用例）；真实 macOS 文件对话框与 Finder 拖入的人工复核仍待做。A02–A04 未开始。

### 5.1 导入前先检查，再决定保存或显示

流程：选择目录 → 本地预检 → 看伙伴与六动作完整度 → 起名 → 保存到伙伴架 / 保存并派去桌面。

默认将新导入素材复制到应用管理目录，原始目录不修改；高级选项可以继续引用外部目录，选择时说明移动原目录会导致失效。旧资料不自动批量搬迁，提供逐只“交给应用保管”。

预检只读，不能创建资料、切换当前伙伴或附加原生窗口。缺少动作、坏图、超过大小限制时指出具体动作和文件；保留选择与名字。原生目录选择/拖入与手输路径最终共用同一预检，网页模式只提供实际支持的文件选择，不能伪造系统路径能力。

### 5.2 素材丢失后重新定位

在已有恢复提示增加“重新定位素材”。选择新目录后先预览和校验；如内容与原记录不一致，明确提示将替换动作素材，确认后才更新该伙伴的素材引用。保留名字、id、当前显示意图；仅修复素材不自动结束休息。

复制、验证或资料提交失败时仍指向旧素材。成功后旧版本保留，不边修复边删除文件。实际显示需要再经过当前伙伴与可见性确认。

### 5.3 完整伙伴包与备份

第一版使用可直接复制的目录包，包含清单、缩略图和六动作文件，不先增加 ZIP 或云服务。导出的内容可在另一台电脑完整导入，不依赖原机器的绝对路径。

默认不包含原始照片、API Key、上传地址、任务日志、活动指针或隐藏/休息偏好。用户选择导出位置；目标同名时创建新名称，不覆盖已有备份。导出不全时标记未完成，不能伪装成可恢复包。

### 5.4 装配草稿

每个动作显示完成度，缺项可直接定位。保留既有逐帧预览和图片限制，增加可访问的前移/后移操作；拖拽排序只作增强。保存草稿不要求六动作齐全，最终保存才要求完整有效。

离开和重启后恢复名字、物种、动作顺序和已选图片；只有本地持久化完成才显示“草稿已保存”。草稿和正式伙伴分离，自动保存不切换桌面；配额/磁盘不足时保留已成功保存的版本并明确告知。

## 6. v0.5：先确认，再投入照片制作

### 6.1 接入和照片用途

服务配置与任务制作分开。现有 Minimax 和自备上传服务继续使用，不引入默认托管服务。清楚说明需要哪些服务、照片会传到哪里、哪些处理在本地进行。Key 默认仅当前会话有效；重启后继续任务需要重新提供。

连接检查若会调用图像生成，必须在点击前说明可能产生请求费用；不能把一次付费生成包装成免费检测。第一次真实上传前确认用途与服务方，服务方变化后重新说明；不每次重复打断已确认的同一任务。

### 6.2 分阶段流程

| 阶段 | 用户看到什么 | 明确的继续条件 |
| --- | --- | --- |
| 照片与特征 | 照片、可选特征描述、上传用途 | 用户点击生成角色图 |
| 角色确认 | 原照片与生成角色对照 | 满意并继续；或调整描述重新生成 |
| 试一个动作 | 默认 idle 的五帧预览 | 满意，生成其余五个动作 |
| 整套制作 | 六动作逐项状态、已完成数量 | 六动作质量检查完成 |
| 最终保存 | 名字、整套预览、保存方式 | 保存到伙伴架 / 保存并派去桌面 |

角色确认前不发动作生成请求；试动作通过后复用该动作，不重复生成。按当前序列图模式，一次顺利完成通常是 1 次角色图 + 6 次动作图请求；重做和错误重试会增加，不据此承诺价格或耗时。

更换照片、物种、生成描述或确认角色版本，会使后续动作不再适配；保留旧版本供比较，新的整套任务只使用一个已确认角色版本。修改展示名字不应单独触发付费重做，生成提示使用的上下文需独立冻结。

### 6.3 持久任务与局部重做

每个已完成步骤先写入本地，再显示完成；重启后显示“上次制作尚未完成”，由用户手动继续，不自动联网或重新付费。任务显示阶段、完成数、具体失败动作和本地保存状态。

请求已经发出但响应或本地保存中断时，标记“上次请求结果待确认”；服务若无幂等或结果查询能力，不承诺自动恢复且不重复计费。确认重新发送前说明可能新增请求。

单动作重做保留旧动作，先预览新旧效果，用户确认后应用新版本；取消或失败保留原伙伴。整套提交继续使用稳定 taskId/pendingPetId，显示失败只重试显示。

可以清除本机任务草稿；清除范围明确到该任务，不删除已保存伙伴或已有备份。不声称能删除第三方已上传副本，第三方删除取决于服务实际能力。

## 7. 批次安排与完成条件

规模是相对实现复杂度，非工期承诺。每批先做一个可运行切片，验证、记录、独立提交并推送，再进入下一批；已有修复只做补验，不重复重写。

| 批次 | 规模 / 依赖 | 最小切片与交付范围 | 出批条件 |
| --- | --- | --- | --- |
| C00 可靠性收尾 | 中；起点 | 旧完成不能覆盖新草稿；伙伴架部分成功回执，随后覆盖所有激活入口 | R01/R02 与旧回归通过，过期恢复不会显示其他伙伴 |
| C01 首屏控制 | 小中；C00 | 上移唯一操作栏，再做紧凑布局与焦点检查 | 默认两种窗口核心控制无滚动可用 |
| C02 原地恢复 | 中；C01 | 当前卡片唤回，再接休息、错误和位置能力 | 不跳页完成恢复，旧恢复入口失效 |
| C03 休息与状态 | 中；C02 | 原生接受 15 分钟，随后补 30/60、托盘与原因说明 | 假时钟与偏好回归通过，真实休眠按 C06 验收 |
| C04 任务直达 | 中；C03 | 空集合直达导入，再扩展任务导航、标签与可选教学 | 原有制作任务可达，切页不丢本次输入 |
| C05 最近移除 | 中高；C04 | 先非当前伙伴移除/恢复，再接当前伙伴和安全撤销 | 数据迁移、跨窗口、重启与显示意图回归通过 |
| C06 实机与观察 | 中；C00–C05 | macOS/Linux 逐项桌面验收，5–8 人完成本期任务观察 | 结果有平台证据；发布条件单独核对 |
| A01 素材基础 | 中；C00、C05 | 只读目录预检、素材清单和原生选择能力 | 不改变活动伙伴；坏图/路径/容量拒绝有效 |
| A02 应用保管与修复 | 中高；A01 | 一只伙伴复制保管，再接引用模式与重新定位 | 复制/提交失败可恢复，旧目录不改动 |
| A03 完整导出恢复 | 中高；A02 | 一只伙伴导出目录包，在新库导入 | 换目录/换机器后仍可播放，备份不覆盖 |
| A04 装配草稿 | 中；A02 | 单动作草稿跨重启恢复，再覆盖六动作与排序 | 缺项可保存草稿，完整才可提交 |
| G01 配置与任务存储 | 中高；A02、A04 | 独立配置、用途确认、本地任务与执行互斥 | 任务不含 Key，重启不自动发请求 |
| G02 角色确认 | 中；G01 | 生成一张角色图，确认/修改与跨重启继续 | 未确认不生成动作，旧版本保留 |
| G03 试动作与整套 | 高；G02 | 先 idle，再生成其余动作，稳定提交 | 中断可继续，重复提交不创建两只 |
| G04 局部重做 | 中高；G03 | 单动作新旧比较与应用、任务本地清理 | 失败不覆盖旧动作，不删除正式伙伴 |
| E01 陪伴探索 | 小规模；C06 观察后 | 手动选择安静/活泼表达、互动文字变化 | 观察用户是否愿意主动再用，未验证不扩大系统 |

## 8. 怎样判断本轮有效

邀请 5–8 名目标用户，优先覆盖不看说明的新手、经常需要安静的日常用户、至少一位带自有素材的制作者。macOS 与 Linux 均需有实际操作证据，不用浏览器代替平台用户。

| 任务 | 预设目标 | 记录方式 |
| --- | --- | --- |
| 收起后找回 | 至少 4/5 无协助，各在约 10 秒内找到入口 | 耗时、首个点击、是否绕路 |
| 理解状态 | 至少 4/5 能分清收起、休息、动画暂停 | 让用户解释结果，不提示答案 |
| 误移除后恢复 | 不丢资料；能发现撤销或最近移除 | 路径、误解、是否误切换当前伙伴 |
| 从伙伴架找回 | 在原页面完成，无需知道产品内部页面结构 | 是否跳页求助 |
| 导入或装配 | 知道还缺哪些动作，失败后可继续 | 缺项识别、草稿恢复 |
| 照片制作 | 上传前知道服务方，整套生成前能确认角色 | 用户原话与是否理解下一次请求 |
| 次日使用 | 记录是否自愿使用及具体原因 | 不预设留存率，不用小样本外推 |

v0.3 先观察控制、状态、误移除和伙伴架找回；导入/装配在 v0.4、照片制作在 v0.5 实施后再观察，不要求尚未开发的任务阻塞 v0.3。次日使用用于探索，不作为发布的留存率门槛。

以上均为建议目标，尚无用户观察结果。仅记录经同意的任务耗时、完成情况、卡住位置与原话；不接入新的远程分析，不采集桌面内容、应用使用记录、Key 或照片。

资源优化先量测后定策略：同一构建和机器上比较显示、低动态、隐藏、主窗口关闭四种状态，记录进程 CPU/内存与播放/调度次数。量测方法及原生验收见验收清单，不凭空承诺 CPU 百分比或电池收益。

## 9. 风险与实施纪律

- 数据迁移和跨窗口行为比页面排版风险更高，独立批次交付；回退代码不能靠删除 IndexedDB 或用户文件完成。
- 状态继续来自 NativePetState；新增显示文案是派生结果，不再维护一份“看起来已显示”的布尔值。
- 先留住用户成果，再改善呈现。复制、生成、导出均使用新目录或版本名，不覆盖原素材、已生成版本或备份。
- 新目录选择能力实施前核对现有依赖与权限；若新增官方对话框能力，仅开放 studio 所需操作，不扩成通用文件系统访问。
- 同一批次不混入工具链升级、供应商更换或无关重构。保留既有回归及方案基线；确需调整测试定位器时保留原场景语义。
- 自动化通过、桌面验收通过、用户观察、签名分发分别记录。任何一项缺失都不能被另一个阶段的成功替代。
