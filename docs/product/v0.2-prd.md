# 首版产品与交互规格

方案代号 v0.2；代码基线 `188d46f`。本文件描述拟实现行为，配套 [工程说明](v0.2-engineering.md) 和 [验收清单](v0.2-acceptance.md)。

## 1. 用户成果与范围

新用户能直接领养内置角色、起名并完成一次轻互动；日常使用时能明确判断伙伴是否在桌面、快速收起和找回；出错后保留已有成果并知道如何继续。

| 必须完成 | 验收边界 |
| --- | --- |
| 领养引导 | 干净安装出现引导；老用户和主动清空用户不被强制重走 |
| 陪伴主页 | 突出伙伴、真实状态、互动和显示控制 |
| 统一设置 | 自主活动、动画、比例、支持的平台能力和自启可见 |
| 隐藏 / 一小时休息 | 不删除伙伴；重启和睡眠唤醒后规则明确 |
| 两个轻互动 | happy / jump 复用；无新美术依赖 |
| 基础错误恢复 | 持续展示、重试、选择已有伙伴、打开制作入口 |
| 保留已有能力 | 导入、帧装配、AI、重命名、删除和空集合持久化不退化 |

本轮不实现自动会议识别、全局快捷键、桌面自由漫步或新的照片上传服务。首版“自主活动”说明为“自动变换姿态”，避免承诺真实位移。

## 2. 信息架构

保持现有三个页面的内部标识 `stage / workshop / shelf`，更新用户可见名称，并在侧栏底部增加设置入口。

| 页面 | 用户可见名称 | 内容顺序 |
| --- | --- | --- |
| stage | 陪伴 | 当前伙伴、真实状态、互动、显示控制；更多动作与预览工具折叠 |
| workshop | 领养与制作 | 现成伙伴；高级制作下保留本地导入、动作装配、照片定制 |
| shelf | 我的伙伴 | 已保存角色、当前选择、重命名、派去桌面、移除 |
| 设置抽屉 | 偏好设置 | 显示与互动、启动、使用帮助 |

“更多动作”保留六动作按钮。“预览工具”才显示播放/暂停预览、逐帧和帧编号；标签一直标明“仅影响此处预览”。主页独立的“暂停桌宠动画”控制真实原生动画。

## 3. 首次领养

### 3.1 进入条件

首次引导依据持久化记录和集合初始化标记判断，不能只看宠物列表是否为空。老版本已初始化用户默认视为已完成引导，包括主动删除全部伙伴的用户。开发过程中热重载、刷新或恢复窗口均不得重复创建宠物。

### 3.2 流程

| 步骤 | 内容 | 主操作 | 旁路与失败 |
| --- | --- | --- | --- |
| 选择 | 现有咕唧、完整形象、简短描述“一个安静陪着你的桌面伙伴” | 下一步 | “先浏览”进入领养页，稍后可继续 |
| 起名 | 默认“咕唧”，最多 20 字符，支持中文输入 | 领养并入住 | “直接使用咕唧”仍完成同一领养事务；失败停留并重试 |
| 见面 | 桌宠已确认加载后，提示摸摸头、拖动、右键和托盘入口 | 完成见面 | “稍后熟悉”直接结束；无需强迫用户进行拖拽 |

名字 trim 后为空时展示“给伙伴起个名字，或直接使用咕唧”，不静默保存空名。命名/确认期间使用现有中文输入法保护，不在 composition 过程中响应 Enter。

点击“领养并入住”后按钮进入“正在邀请…”，同步锁定重复点击；仅在素材、原生应用和资料保存完成后进入见面步骤。若本地资料已提交而列表刷新失败，读取已保存宠物恢复界面，不能再次创建。

见面步骤允许点击页面里的伙伴代替桌面触摸，键盘也能完成。提示“关闭这个窗口后，我仍会在桌面。需要我时，从菜单栏/托盘打开。”只在真正原生模式显示；浏览器展示“这是网页演示，桌面能力需在应用内体验”。

### 3.3 已有用户与空集合

已有用户继续使用当前伙伴，欢迎信息只出现一次，可随时从帮助重新查看教学。主动清空后的页面展示“这里暂时没有伙伴”，主操作“去领养”，次操作“导入已有伙伴”；重启不自动补回咕唧。

## 4. 陪伴主页

默认标题“今天，{名字}陪着你”。角色区域保留充分留白；状态条靠近名字。主页主操作为“摸摸头”“打个招呼”，次操作为“暂时收起”“休息一小时”和“偏好设置”。隐藏/休息后对应位置切换为“立即唤回”。

| 条件，按优先级判断 | 状态文案 | 可执行操作 |
| --- | --- | --- |
| 网页模式 | 网页演示 | 页面内模拟，不能声称控制系统桌面 |
| 无伙伴 | 等待领养 | 去领养、导入 |
| 资源/原生错误 | 需要帮助 | 重试、查看已有伙伴、打开制作 |
| 加载或命令确认中 | 正在准备 / 正在同步 | 显示过程，阻止重复提交 |
| snoozed | 休息中，{本地 HH:mm}回来 | 立即唤回 |
| hidden | 已收起，随时可以叫回来 | 唤回 |
| shown + 动画暂停 | 安静陪着你 · 动画已暂停 | 恢复动画；互动暂不可用 |
| shown + 低动态 | 安静陪着你 · 低动态 | 文字互动；设置内可调整 |
| shown + 自主活动关 | 在桌面陪着你 · 固定姿态 | 互动、开启自主活动 |
| shown + 正常 | 正在桌面陪着你 | 全部正常操作 |

“在线”不用来表达本地桌面展示。显示控制结果以原生确认状态为准，等待时保留上一次确认状态并显示“正在同步”；失败保留/恢复确认状态，展示对应恢复操作。

## 5. 显示、休息、暂停的规则

| 操作 | 伙伴窗口 | 动画与自主行为 | 持久化 / 恢复 |
| --- | --- | --- | --- |
| 暂时收起 | 隐藏 | 不消耗动作时间，不安排自主活动 | 保持隐藏，直到显式唤回；重启保持 |
| 休息一小时 | 隐藏 | 同上 | 保存到期时刻，重启按剩余时间恢复 |
| 立即唤回 | 显示当前伙伴 | 保留动画暂停和自主活动偏好 | 清除休息时刻；恢复后当前动作从头开始 |
| 暂停桌宠动画 | 仍显示 | 当前画面停住，自主调度暂停 | 本次应用会话保留；重启恢复播放，与当前基线一致 |
| 关闭自主活动 | 仍显示 | 动画可继续，停止自动换动作 | 跨重启保存；手动动作和互动仍可用 |
| 暂停预览 | 桌宠不变 | 仅页面预览停止 | 页面级状态 |
| 关闭主窗口 | 桌宠不变 | 不改变以上偏好 | 见面教学提前解释托盘恢复，关闭时不强制确认 |
| 退出应用 | 全部退出 | 停止 | 保留显式隐藏/休息/自主活动设置 |

一小时休息支持提前唤回；系统睡眠跨过到期时刻时，在唤醒后检查一次，当前伙伴健康才恢复。已删除最后一个伙伴、应用退出或资源错误时，不自动创建或展示其他角色。休息期间手动隐藏改为隐藏且清除计时；手动派新伙伴去桌面是显式显示意图，清除隐藏/休息；后台资料补全和应用启动不属于显示意图。

恢复时暂停偏好仍有效，不因唤回自动播放。隐藏过程中不累积帧时钟；唤回从当前动作首帧重新播放，暂停时停在该首帧。自主活动开启时，从恢复显示起等待 5 秒再安排下一次切换。

首版固定“一小时”，不添加自定义日期、自动会议/全屏识别。系统时钟明显变化时立即重新核对到期时间；不额外持续轮询用户系统活动。

## 6. 轻互动

| 入口 | 反馈 | 限制 |
| --- | --- | --- |
| 点击伙伴主体 / 摸摸头 | 播放 happy；主界面可显示“收到你的摸摸了” | 同一伙伴全入口共享 1.5 秒冷却 |
| 打个招呼 | 播放 jump；可显示“我在这里！” | 同上；不移动系统窗口 |
| 拖拽伙伴 | 移动、保存位置 | 与单击分开，拖动不触发 happy |
| 透明区域 | macOS 保留已有穿透 | Linux 暂未支持时隐藏该设置，明确能力说明 |

采用现有 macOS 3pt 拖拽阈值；Linux 需补齐等价的“释放时识别单击与拖拽”规则。冷却内不叠加动画或提示，不弹错误。手动动作/互动保留现有 20 秒自主行为冷却。低动态偏好只显示文字和轻微色彩反馈，保留底层动作状态但不自动播放交互动画。

隐藏、休息或用户显式暂停期间不自动唤醒来响应互动。按钮旁分别解释“先唤回伙伴”“先恢复动画”；没有可用伙伴时禁用。仅低动态生效时仍允许文字互动。原生窗口不新增抢焦点的气泡窗口；第一版文字反馈只出现在主界面，桌面通过现有动作帧反馈。

## 7. 设置与托盘

设置抽屉包含：桌宠动画、自主活动、比例（复用 50–150%）、重置位置、可用时的透明区域穿透、开机自启、减少动态效果和重新查看教学。自启显式由用户开启，不因领养而开启。

“减少动态效果”默认跟随系统，用户可选始终减少；默认不改变既有桌宠播放习惯，减少时页面过渡、互动动作和自主动态表现必须遵从相同规则。工程实现必须将该偏好传到原生侧，不能只改 CSS。详细合成规则见工程说明。

托盘顶部增加当前名字与状态，然后提供：打开主界面、显示/收起、休息一小时/立即唤回、播放动画、自主活动、更多动作、位置和自启、退出应用。右键菜单复用适用操作。托盘勾选和主界面控件一起更新，失败不得显示虚假的成功勾选。

当前 Linux 重置位置、位置持久化与穿透存在能力差异。首版按能力展示，未实现项不出现可点击的空操作；主界面有统一的“当前系统支持情况”说明。

## 8. 错误恢复

| 情况 | 持续展示的主文案 | 操作 |
| --- | --- | --- |
| 当前资源找不到 | 暂时找不到 {名字} 的动作素材，资料仍在 | 重试加载、选择已有伙伴、打开制作 |
| 原生应用失败 | 暂时没能把伙伴带到桌面，原来的伙伴已保留 | 重试、查看详情 |
| 设置保存失败 | 这次设置没有保存，请再试一次 | 重试对应操作；保留上一次确认值 |
| 资料保存失败 | 还没保存成功，名字和选择都保留着 | 重试、返回修改 |
| 自启失败 | 未能开启开机启动，其他功能可以继续使用 | 重试、简短系统原因 |

错误详情按需展开，可复制经过脱敏的阶段/错误码，不含原图、API Key、签名 URL 和完整服务响应。首版“重新定位文件夹”的原生选择器不作为前置条件，可先跳转现有工坊并保留待修复伙伴上下文；未实现选择器时不要放置无效按钮。

成功提示可短暂显示，阻断错误保留到解决或用户关闭；关闭提示不清除失败状态，用户回到页面仍可找到恢复入口。已确认数据库提交后只做界面重读，不再提示用户重新创建。

## 9. 视觉与可访问性

沿用温暖、安静的视觉方向：米白背景、白色内容面板、深棕正文、焦糖色主操作。按钮文字需与背景满足常规文本 4.5:1 对比度；浅金色用于装饰和选中背景。正文建议 14px，辅助文字至少 12px；图标操作有可读名称。

| 窗口宽度 | 布局 |
| --- | --- |
| ≥1000px | 200px 侧栏，主体角色与控制区两列 |
| 840–999px | 72px 图标侧栏带名称提示，内容和控制上下排列 |
| 最小目标 | 840×620，无横向滚动，主要操作可滚动到达 |

正式应用需同步调整 Tauri 最小窗口限制，不能只修改 CSS。Tab 能遍历控件，焦点边框清晰；抽屉/对话框限制焦点，Escape 关闭并还原焦点；反馈使用适度的 `aria-live`，避免每帧朗读。输入框有显式标签，键盘能完成领养和所有控制。

原型提供页面与交互结构参考；颜色、尺寸可在保持这些可用性约束的前提下微调。原型中的“演示数据”工具条不进入正式产品。
