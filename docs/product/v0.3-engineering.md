## 2. C00：把保存、切换与显示分开确认

### 2.1 领养进度写入

实现或复用进行中的 `saveOnboardingProgress`，规则如下：

1. 显式新领养只走 `startNewAdoptionIntent`。旧记录缺 intentId 的迁移和首次初始化，各有受限入口；初始化只能在事务确认记录不存在时写入。
2. 普通命名、下一步、先浏览、跳过、完成均在同一读写事务中检查 intentId。不同意图不能因 updatedAt 较新而写回。
3. 同意图内，committed/completed 不接受迟到的较早阶段；claim/commit 的稳定 adoptionId/pendingPetId 继续复用，不重分配。
4. 完成见面还要确认持久化 confirmedPetId 与该意图一致，phase 已 committed，且 displayConfirmed 为 true。网页使用其演示适配层的确认规则，不伪装原生确认。
5. 进度接口返回实际持久化记录，不返回未经保存的输入。过期、版本冲突与真实存储错误要可区分；存储故障不能统一称为“进度过期”。

同意图内的并发编辑使用可比较的 `progressRevision`：旧记录缺失按 0 读取，事务校验调用方读取到的版本，成功后 +1；时间戳仅用于展示或历史，不能当授权或先后顺序的唯一依据。claim、commit、显示确认也维护该版本，幂等读取不增加版本。

异步保存回复不得覆盖用户刚输入的新名字：调用时记录本地编辑序号；回复时只有序号未变化才回填表单。发生其他窗口冲突时保留本地未保存输入，说明“另一窗口已更新”，由用户选择使用最新记录或重新输入；不默默合并两个领养意图。

### 2.2 激活结果与显示重试

以下是目标接口形状，不是现有可直接调用的 API；先实现伙伴架最小切片，再替换导入、装配和 AI 调用方。

```ts
// src/pet-activation.ts 的接口草案；PetProfile/NativePetState 引用现有类型。
type ActivationResult =
  | { status: "displayed"; pet: PetProfile; state: NativePetState }
  | { status: "webPreview"; pet: PetProfile }
  | { status: "savedOnly"; pet: PetProfile }
  | { status: "displayPending"; pet: PetProfile; retry: DisplayRetryContext; code: string }
  | { status: "superseded"; currentPetId: string | null };

interface DisplayRetryContext {
  operationId: string;
  petId: string;
  intentId?: string;
  selectionRevision: number;
  nativeVersion: { sessionId: string; revision: number };
}
```

保存前失败走明确的错误路径；资料提交后的显示失败返回 displayPending，不回滚成“没保存”。只在合并后的原生快照 petId 匹配、availability=ready、visible=true 时报告 displayed。网页成功使用 webPreview 文案。

维护 `metadata.selection_revision_v1`：初值为 0；每次明确选择、创建并激活、领养提交、移除导致的活动替换均在事务内递增，即使用户再次明确选择同一只也递增。重命名、动作同步、预览和列表重读不递增。

重试前检查伙伴仍在正常集合、活动 id 和 selectionRevision 仍匹配；领养还要检查 intentId、confirmedPetId 与 phase。任何不匹配都返回 superseded 并读取最新资料，不重新创建、重新附加旧伙伴或展示旧成功文案。

只做前端预检查仍有竞态：在 Rust 控制服务内为面向某伙伴的 show / snooze / resetPosition，以及有目标的 detach 增加可选 expectedPetId，并在执行变更的同一串行段检查。托盘“操作当前伙伴”可以不传；卡片和迟到重试必须传。目标变更返回 TARGET_CHANGED，不修改显示意图、不污染新伙伴的错误状态。网页适配层遵守相同目标检查。

针对显示重试再增加可选 expectedState（sessionId/revision），记录失败处理后的最新确认版本，并在原生执行处比较；校验应在本请求自身写 pending、清除错误或增加 revision 之前完成。这样，即使同一只伙伴被另一窗口或托盘改成保持收起，旧 show 重试也不能覆盖它。版本已变化时重读并失效旧入口；用户可以重新点击当前页面的显式唤回，不在后台替换版本后自动重发。本期接受严格版本比较带来的保守失效，不新建另一套原生意图状态。

重试只发 show，不再次 save/claim/生成素材。`lastPreferenceRef` 或等效重试记录在每次显式偏好操作时更新；旧 show 失败后又执行 hide，旧恢复入口立即失效，不能重放旧操作。

未解决的部分成功在当前会话保持持续入口，所有页面共用同一上下文。刷新时用当前资料和 NativePetState 重建可确认的恢复入口；无法证明上下文仍有效时回到当前伙伴控制，提供显式唤回，不凭隐藏状态猜测旧任务仍待显示。领养继续依赖其已持久化 displayConfirmed；进程重启不自动执行普通显示重试。

### 2.3 不宣称跨 Rust / IndexedDB 原子提交

两侧不存在一个共同事务，沿用“预检 → 资料事务 → 原生应用 → 重读确认”的可恢复流程。单窗口复用 serial；多窗口依赖事务条件与原生目标检查，不能把 React busy 当成互斥保证。

资料事务前的失败保留旧资料；资料事务后的失败保留已提交结果，标记待同步。任何补偿都先核对当前活动选择；不能因旧操作失败而重新激活已被新操作取代的伙伴。原生 attach 继续使用 attach_seq，调用方不把被取代的加载结果当成功。

## 3. C01–C04：界面与休息接口

### 3.1 布局和导航

`CompanionControls` 是唯一核心操作栏，放到 `CompanionPage` 预览前；同一 DOM 通过 CSS 调整布局，不复制隐藏按钮。吸顶相对 `.app-content`，为焦点滚动留出 scroll-margin；错误条不被吸顶层遮挡。首屏测量基于可见矩形，不能只断言元素存在或“可滚动到达”。

`PetShelf` 接收当前快照、能力和有目标 id 的控制回调；组件不自己 invoke，也不将非当前卡片与原生状态关联。将操作结果和恢复上下文放在上层控制服务，卡片卸载不丢操作。

工坊任务入口采用受控参数 `preset / frames / manual / ai` 的单一映射，先统一现有类型与组件内部不同命名，再接按钮跳转。可在上层维护 `{ task, draftId?, repairPetId? }`；当前任务和输入移到不会随页签卸载消失的位置。v0.3 保留会话状态，v0.4 才承诺跨重启草稿。

修复素材与新建入口明确区分：带 repairPetId 的任务只能更新匹配伙伴，不能调用默认创建并激活的旧保存函数。抽屉、休息选项和恢复面板均复用现有焦点管理，不引入第二个弹层系统。

### 3.2 可变时长的兼容扩展

前端目标请求是 `{ kind: "snooze", durationMinutes?: 15 | 30 | 60, expectedPetId?: string }`。缺省继续等于 60 分钟；Rust 的 serde 映射接受同样 camelCase 字段。不能只改 TypeScript 而让 Rust 继续忽略时长。

Rust 只接受 15/30/60 的整数值；0、负数、超范围、溢出和错误类型拒绝且不改确认值。后端使用自己的 now_ms 计算绝对 snoozeUntilMs，不能采用客户端计算的任意到期时刻。网页适配层用可注入的 now，保持相同验证和行为。

NativePetState 现有字段足够；native-pet-settings.json 仍存绝对到期时刻，schema v2 无需仅因增加请求参数而升级。原来的一小时请求、已保存的一小时到期和重启恢复继续兼容。

| 操作 | 状态变化 | 必须保留 |
| --- | --- | --- |
| 选择休息时长 | mode=snoozed；until=后端当前时刻+时长 | 暂停、自主活动、比例、当前伙伴 |
| 调整休息 | 从当前时刻重新计算，替换旧 until | 同上 |
| 提前唤回 | mode=shown；until=null | 显式暂停仍有效 |
| 保持收起 | mode=hidden；until=null | 不被旧定时器再次唤回 |
| 到期、睡眠后检查 | 健康的当前伙伴才显示；只处理一次 | 无伙伴时不创建；素材错误不偷偷替换 |

主界面、托盘调用相同控制服务。托盘增加三个休息时长；现有右键动作入口不另建一套状态。剩余时间的页面刷新不触发偏好更新，后台页面不保留高频计时器。

状态说明从 NativePetState 派生，原因顺序与产品方案一致。朗读只报告操作/阶段变化，不朗读每帧、每秒剩余时间或频繁 revision。

## 4. C05：最近移除与安全撤销

### 4.1 存储和迁移

基线数据库为 `desktop-sticker-pet-db` version 2，现有 stores 为 pet、pets_collection、metadata。规划 version 3 新增 removed_pets（keyPath=id）；如果实施时版本已被其他合法迁移占用，应合并迁移并选择下一版本，不覆盖已有结构。

```ts
// src/storage.ts 中的目标持久化形状。
interface RemovedPetRecord {
  id: string;                 // 原伙伴 id；一只只保留一份最近移除资料
  removalId: string;          // 本次移除操作，区分移除-恢复-再次移除
  pet: PetProfile;
  removedAt: string;
  wasActive: boolean;
  selectionRevisionAfterRemoval: number;
}
```

软移除在同一事务内完成：读取并校验当前活动选择 → 写 removed_pets → 删正常集合记录 → 必要时更新 active_pet_id 和 pet/current 兼容镜像 → 增加 selectionRevision。只有事务完成才广播。

保留 collection_initialized 与原领养记录，最后一只被移除后重启仍是老用户空集合。loadAllPets/readActive 的旧库回退必须排除已移除 id，不能从 pet/current 或旧 localStorage 复活它。运行时动作、迟到的 rename/save、旧领养提交不能重建最近移除中的伙伴；只有显式恢复可以移回正常集合。

没有新数据时，升级不搬动或改写原有伙伴与素材。onversionchange 关闭连接；被旧窗口阻塞时说明关闭旧窗口重试，不删库重建。

### 4.2 当前伙伴移除与原生同步

替代伙伴按 createdAt、id 稳定排序选择；先检查其素材可加载。若替代素材损坏，保留原状态，提示先修复或选择另一只，不悄悄落到默认角色。非当前伙伴移除不触发原生 attach。

事务提交后原生同步必须重新核对活动选择版本。显示意图仍由 Rust 保管：hidden 保持隐藏，snoozed 保持同一个 until，shown 才允许健康的替代伙伴按当前意图显示。最后一只移除后 detach，不清空最近移除记录。

如果资料已移除但原生应用失败，保留最近移除和新指针，显示“资料已移除，桌面尚未同步”，重试以最新活动选择为目标。不能让旧失败补偿覆盖用户后来做出的选择；针对旧伙伴的 detach 也要校验目标。

### 4.3 两种恢复策略

接口区分 `restoreRemovedPet(id, removalId, "undo" | "shelf")`，事务检查 removalId，已恢复的重复调用返回现有记录。

- shelf：只移回正常集合，不修改活动指针、不发送 show。
- undo：仅 wasActive=true 且当前 selectionRevision 等于移除后的版本时，才恢复原活动选择并增加版本；否则等同 shelf。

恢复使用最近一次移除保存的完整资料。图片/原目录丢失不阻止资料回架，标记素材待恢复；不能假报已显示。恢复原活动选择后的原生同步同样需要目标检查，保留当时最新的隐藏/休息/暂停偏好。

最近移除默认持续保留。v0.3 不做自动过期、批量清空或素材物理删除，因此旧版代码回退前需导出可恢复资料，不能把降级后打不开新库当成允许删除数据库。

## 5. v0.4：素材、导入与目录包

### 5.1 素材引用与所有权

在 PetProfile 增加可选 assetId、assetRevision（缺失按 0）；保留 frameRoot/storageMode 兼容现有资料，加载器统一解析。新素材由 Rust 生成不可变 assetId，写入应用数据目录下 managed-assets/<assetId>/，每个版本新目录。内置包、应用保管包、外部引用包三类所有权明确，不能从路径字符串猜测删除权限。

旧资料没有 assetId 时继续按旧路径读取；用户主动“交给应用保管”才复制并写新引用。不要启动时遍历用户目录或重新编码所有图片。

新设 `savePetProfile` 或等效资料接口，只保存到集合；现有 savePet 的激活副作用不能用于“仅保存”。“保存并派去桌面”才进入激活流程，恢复素材只更新匹配资料的引用。

### 5.2 预检、复制与提交

目标接口分为 inspectFrameDirectory、copyToManagedAsset、commitPetAssetReference；名称可适配仓库风格，但三步副作用不能混合。

预检复用 frame_pack.rs 的解码和容量规则，返回每动作数量、缺项、图片问题、总量与有限缩略图。现有限制作为共同来源：六动作各 5–60 帧，单图不超过 16 MiB、2048×2048，文件总量不超过 128 MiB、解码总量不超过 256 MiB。前端只作提前提示，Rust 是最终校验。

正式确认后重新校验源文件，防止预检后内容改变。复制到本次 staging 目录 → 验证全部文件 → 同文件系统原子改名成新 assetId 目录 → 条件更新 IndexedDB 引用 → 原生确认。copy 或提交失败不修改旧引用；暂存清理只允许本次未引用的任务文件，不能清理原目录或已有资产。

新增目录选择使用官方 Tauri v2 dialog 能力，实施时确认兼容版本并更新锁文件；studio 仅开放所需目录选择权限，不为此开放通用文件系统或其他窗口权限。取消选择没有副作用。拖入目录和手输目录进入相同 Rust 预检。

重新定位携带 repairPetId、预期 assetRevision 和原素材引用；提交事务比较这些值，成功后增加 assetRevision。用户已删除或替换该伙伴时拒绝旧结果。内容变化先预览确认，只有修复素材不调用 show。

### 5.3 可移动目录包 v1

第一版结构为 pet-package.json、thumbnail.png、frames/ 下的六动作目录。清单的目标模型如下；这是格式定义，不是现有示例文件。

```ts
interface PortablePetPackageV1 {
  format: "desktop-sticker-pet";
  formatVersion: 1;
  pet: { name: string; species: "cat" | "dog"; style: "q-sticker"; createdAt: string };
  actions: Record<PetAction, Array<{
    path: string;   // 相对目录包根路径
    sha256: string;
    width: number;
    height: number;
  }>>;
}
```

清单不超过 64 KiB，素材沿用上述帧包限制。只接受包内相对路径，拒绝绝对路径、..、符号链接越界、重复引用和未知格式版本；图片解码与散列必须验证。清单内数组顺序是播放顺序，旧裸六目录导入仍按现有文件名排序。

导出先写新临时目录，完整校验后再形成最终新目录；目标已存在时产生递增名称或要求用户另选，绝不覆盖。缩略图从动作帧派生，不能直接复制可能含原图的旧 sourceImage；原始照片和敏感生成信息不进入默认包。导入默认为新伙伴，分配本机新 id，不采用包内活动状态；显式确认后才保存或显示。

应用只导出本机实际可读取且完整的素材；引用丢失就报告缺失，不生成空壳备份。保留现有散列/图像库；如需新增散列依赖，先核对锁文件并单独限制变更范围，不连带升级工具链。

### 5.4 装配草稿与版本

规划数据库 version 4 新增 creation_drafts；旧 schema 只作增量迁移。原生草稿保存小清单与本机草稿文件引用，网页草稿用 IndexedDB Blob；不把全部图片或 Key 写入 localStorage。

草稿包含 schemaVersion、draftId、revision、name、species、各动作帧顺序和对应文件引用。每次更改防抖约 800ms 保存，离开前等待已开始的保存；最后写入使用 revision 条件，避免跨窗口覆盖。持久化失败保留内存输入并明确未保存，不能显示已保存。

正式提交前重用同一图片校验；为草稿分配稳定 pendingPetId，防止保存成功后刷新造成重复伙伴。新增/重排图片产生新版本，已有图不原地覆盖。正式伙伴引用的资产不随草稿丢弃而删除。

## 6. v0.5：持久照片制作任务

### 6.1 存储与执行权

原生任务存储在应用数据目录 generation-tasks/<taskId>/，包含 schemaVersion=1 的 task.json 和分版本媒体文件。元数据由 Rust 原子写入；不直接把含 URL 的旧 GenerationCheckpoint 原样 JSON 序列化。

目标字段：taskId、revision、ownerSession、stage、pendingPetId、photoDigest、species、appearanceNotes、promptVersion、characterRevision、confirmedCharacterRevision、各动作版本/状态、请求回执、committedPetId。图片使用本机相对文件引用。Key、完整带凭据地址、带签名远程 URL 和原始服务响应不进入 task.json。

本机任务可能包含照片与描述，首次创建时说明本地保存用途；使用应用私有数据目录和平台允许的严格权限，不放入仓库。远程图片 URL 仅留当前会话；重启后必要时重新上传，用户继续前先说明。不得在普通诊断中输出原图、Key 或私密 URL。

同一任务一次仅一个执行者；Rust 通过 taskId/revision 和进程 session 分配执行权，所有写入和网络步骤校验执行权及 attemptId。其他窗口只读并提供“查看当前制作”。进程重启后旧执行权失效，任务标记 interrupted；明确继续才能重新获取，不因页面挂载自动执行。

保留现有 JS 本地图像处理能力，先以“前台执行器 + Rust 持久步骤提交”落地，不要求一批重写所有算法到 Rust。任务在隐藏主窗口时尽力继续本次运行；退出应用或执行器销毁后停止并可恢复，不承诺后台独立服务。

### 6.2 阶段和请求回执

| 阶段 | 完成落盘内容 | 下一步 |
| --- | --- | --- |
| draft | 本机照片/摘要、配置描述，不含 Key | 用户确认上传并生成角色 |
| characterGenerating | attemptId 和请求开始状态 | 成功保存角色新版本，或进入 uncertain/failed |
| characterReview | 可预览的角色文件 | 用户确认版本后才进入试动作 |
| sampleGenerating / sampleReview | 默认 idle 五帧及确认结果 | 复用已确认 idle，生成剩余动作 |
| actionsGenerating | 每个完成动作的文件与质量结果 | 六动作完整后 readyToSave |
| readyToSave / committing | 稳定 pendingPetId、目标 assetId | 确认正式资料提交 |
| committed | committedPetId 与保存/显示结果 | 显示失败只恢复显示 |
| interrupted / failed / uncertain | 已完成步骤与脱敏错误、上次有效阶段 | 用户手动处理后继续 |

每次发网络请求前原子记录 attemptId/start；响应内容保存成功后才标记 succeeded。网络已发送但没有可用回执或落盘证据时是 uncertain，不直接自动重发。若服务支持结果查询或幂等键，使用其真实能力；不支持时明确告知重新发送可能新增费用。

阶段进度按“角色已确认 / 已完成 3/6 动作 / 正在保存”等实际结果展示，不使用虚构百分比和剩余时间。取消在安全步骤边界停止；正在提交时锁定破坏性取消，重开后查询是否已提交，不重新分配 petId。

配置检查优先使用服务真实提供的非生成接口；如果只能生成测试图片，必须明确其请求性质。任务继续需要重新输入 Key，不能为方便续传悄悄持久化凭据。

### 6.3 变更失效与局部重做

signature 由照片摘要、物种、生成描述、promptVersion、模式、去背景设置、已确认角色版本构成；展示名字独立于生成输入。不要继续把带私密 URL 的字符串或照片 data URL 用作可打印 signature。

角色更换使其后动作失效，但旧文件和旧确认版本保留。新任务动作必须绑定同一个 confirmedCharacterRevision；不能把两个角色版本的动作拼在一起。

单动作重做写 candidate 版本，质量检查和预览通过后由用户明确应用；生成失败、取消或比较后放弃，都不覆盖已接受动作。正式伙伴应用新动作生成新的完整 assetId，并条件更新资料引用；资料更新失败仍保留旧伙伴。文件命名使用递增版本/唯一 id，不覆盖已有成品。

正式伙伴、最近移除和其他草稿不得直接引用 generation-tasks 内部文件；接受成果时复制或晋升到独立 managed-assets 版本，其他任务复用输入也需建立独立保管引用。清除前锁定任务 revision、停止其执行权并确认没有在途提交，防止清除后迟到回调重新写入。

清除任务只处理该 taskId 所有且未被正式资料、最近移除、其他草稿或备份引用的本机文件。先展示清除范围并重新核验引用；发现历史直接引用或无法证明归属时保留文件并说明原因。第三方远程副本不属于本地清除的成功承诺。

## 8. 出批、回退与交付门槛

每批按影响面运行 npm test、npm run build；改 Rust 时使用独立 CARGO_TARGET_DIR 运行 `cargo test --manifest-path src-tauri/Cargo.toml --locked` 与对应平台 check，保留 macOS/Linux CI。帧处理/素材包有变更时运行 frames:check 及相关 Rust 校验；已通过且无相关变化的检查不重复堆叠。

浏览器流程继续用 tools/verify-workflows.mjs，使用临时 PET_EVIDENCE_DIR、现有 PET_PLAYWRIGHT_MODULE、稳定 PET_PREVIEW_URL 和实际 PET_CHROME_PATH；先检查服务监听及 cwd，再复用或启动。脚本不能连外网、读真实库或使用真实 Key。不为流程脚本给生产依赖加入 Playwright。

新增数据读写必须有旧库、空库和阻塞迁移验证。回退优先关闭新入口并保留向后读取兼容；新库/素材不允许通过删除恢复旧版本。部署回退若旧二进制无法读新 schema，提供经过验证的恢复构建，不直接启动破坏性降级。

每批交付记录包含实现提交、验证命令和结果、迁移影响、平台实测、已知限制。签名/公证、安装分发和真实桌面验收仍按既有 [macOS 分发说明](../release-macos.md) 与验收清单执行。设计完成、代码完成、自动化通过、桌面验收和对外发布必须分别标记。
