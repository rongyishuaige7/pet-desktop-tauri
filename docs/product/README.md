# 桌面贴贴宠物：下一阶段设计与实施入口

设计基线：`188d46f`，2026-10-21。状态：可实施的产品方案；所有“新增”行为均尚未接入应用。本目录只交付设计文档和独立原型，不修改运行代码、依赖、真实用户数据或安装包。

产品主线：用户快速拥有一个伙伴，工作时能随时控制它，通过少量自然互动建立陪伴感。首轮面向 macOS / Linux 的个人桌面用户，保持本地使用路径。

## 首版决策

| 决策 | 首版边界 | 原因 |
| --- | --- | --- |
| 内置角色 | 用现有“咕唧”完整跑通领养；新增角色接入数据清单 | 新角色美术不阻塞首版验证 |
| 首次体验 | 选择伙伴 → 起名并入住 → 试一次互动；可跳过教学 | 快速感知价值，并支持键盘和低动态用户 |
| 日常控制 | 显示 / 隐藏 / 休息一小时 / 播放暂停 / 自主活动 | 解决用户的可控性和操作歧义 |
| 轻互动 | 摸摸头、打个招呼，复用 happy / jump | 先验证反馈体验，保持素材和工程规模可控 |
| 控制入口 | 主界面、真实托盘、右键菜单使用同一原生状态 | 用户从任意入口操作都能看到真实结果 |
| 浏览器 | 明确“网页演示”，不显示“桌面在线”或伪造系统能力 | 与原生运行结果清楚区分 |
| 免打扰 | 手动隐藏和一小时休息；不检测会议、前台应用或录屏 | 无需新增系统读取权限 |
| 制作能力 | 保留现有导入、装配和 AI，归入高级制作入口 | 继续服务已有用户 |

首版不含：新 AI 服务或生成链路重写、真实漫步位移、性格/成长系统、专注计时、全局快捷键、云同步、社区、多宠物同屏和 Windows 原生窗口。

## 怎样判断方向有效

先邀请 5–8 名目标用户，在获得同意后观察实际操作。以下是验证目标，不是已有统计结果。

| 问题 | 操作定义 | 首轮目标 |
| --- | --- | --- |
| 能否独立上手 | 从第一次界面出现到成功入住并触发反馈 | 至少 4/5 无人工协助，典型用户约 60 秒 |
| 是否能控制打扰 | 给出“开会时收起，结束后找回”任务 | 隐藏和恢复各能在 10 秒内找到 |
| 是否理解状态 | 询问隐藏、暂停、休息分别发生什么 | 至少 4/5 能正确区分 |
| 是否愿意留下 | 次日自愿继续使用，询问具体原因 | 收集行为和原因，不预设留存结论 |
| 是否稳定 | 睡眠唤醒、重启、托盘、空集合等验收 | 阻断问题为 0，见验收清单 |

观察记录只需耗时、是否完成、卡住的位置和用户原话；首版不接入自动分析服务，不采集照片、密钥、桌面内容或应用使用记录。

## 本次设计交付验证

2026-10-21，独立原型在 Chrome 中通过 10 个流程检查：首次领养、互动中暂停与键盘焦点、隐藏与托盘恢复、暂停后隐藏/恢复、休息到期、低动态与 Escape 焦点返回、Linux 能力、持续错误与重试、840×620 布局、空集合重新领养。页面脚本无运行错误；已检查领养、陪伴、设置和紧凑布局截图，Markdown 本地链接和 JavaScript 语法检查通过。

这些结果只验证设计原型，不表示正式应用已实现新功能；重启、睡眠唤醒、原生窗口和平台操作仍须在实施后按验收清单完成。
